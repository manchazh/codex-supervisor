# Что подтверждено, а что ещё предстоит доказать

Это **обезличенная сводка исторических исследований на Windows**, а не отчёт о тестах текущего публичного репозитория. Персональные пути, внутренние Issue/PR, точные thread ID, приватные чаты, ключи и логи **намеренно не публикуются**.

| Возможность | Состояние | Проверенное основание / ограничение |
| --- | --- | --- |
| Обычный Codex CLI, интерактивный чат | Подтверждено в отдельном проекте | Сессия запускалась, выходила в меню, история и scrollback доступны |
| Запуск через отдельное окно PowerShell 5.1 | Подтверждено в отдельном проекте | Реальный ручной сценарий запуска и resume прошёл на Windows 10; **переносимого установщика здесь пока нет** |
| `app-server thread/start` и новый `turn/start` | Подтверждено ограниченным опытом | Два коротких реальных модельных хода в одноразовом изолированном тестовом Git; не на проекте пользователя |
| `thread/resume` с тем же ID и контекстом | Подтверждено ограниченным опытом | Второй процесс app-server продолжил тот же thread и корректно использовал ранее сообщённый нейтральный маркер |
| Открытие истории app-server в обычном Codex TUI | Подтверждено ручным просмотром | Было видно два предыдущих запроса и два ответа; **внешний ход в уже открытом окне не тестировали** |
| `exec --json` | Реальная попытка с неизвестным исходом | Один опыт завис без JSONL и был остановлен по таймауту; не повторялся |
| `exec resume` | Не проверено | Наличие команды в `--help` не доказывает корректное продолжение |
| `queue` и remote TUI | Исследована доступность интерфейсов | Доставка в живую сессию, отмена и отсутствие дублей **не доказаны** |
| Распознавание подписочной квоты и серверного восстановления | **Не проверено на живом лимите** | В схемах экспериментального API встречаются `usageLimitExceeded`, `resetsAt`, `ordinaryUsageAllowed`; реальная семантика требует проверки |
| Автоматическое продолжение после лимита | **Не реализовано и не проверено** | Только имитационные PoC с виртуальным временем и фиксированными событиями |
| Windows sandbox и `node_repl.exe` | Подтверждён локальный сбой окружения | В одной установке CLI 0.162.1 `elevated` sandbox падал с Windows error 32 на ACL занятого EXE. Это **не означает**, что сбой воспроизводится у всех пользователей |
| GUI Supervisor, инсталлятор, поддержка разных проектов | **Ещё не реализованы** | Цели MVP |

## Правила интерпретации

1. **Help/schema ≠ результат живого теста.** Поддерживаемый флаг не доказывает устойчивость протокола.
2. **Mock ≠ настоящий Codex.** 100 зелёных unit-тестов без реального backend — лишь проверка логики макета.
3. **Просмотр истории ≠ возможность безопасно управлять открытым TUI.** Внешние новые ходы требуют отдельного доказательства.
4. **Появление времени reset ≠ восстановленная квота.** Необходима свежая серверная проверка соответствующего аккаунта/лимита.
5. **Unknown ≠ fail и ≠ success.** Если результат действия не установлен, никакого безусловного повторного запуска.
6. **Локальная песочница ≠ часть Supervisor.** Не ослаблять её ради видимого успеха прототипа.

## Как фиксировать следующие эксперименты

Каждый протокол должен содержать: дату и версии (без персональных путей), цель, границы согласия пользователя, входные условия, конкретные команды/вызовы без секретов, ожидаемый результат, фактический вывод, число модельных ходов, было ли остановлено, отдельное подтверждение ограничений и последствия для архитектуры. Секретные детали хранить локально вне Git.

До доказанного реального quota reset автоматическое восстановление должно быть **выключено** и обозначено экспериментальным.
