# MVP Codex Supervisor: работающий прототип интерфейса

**Состояние:** первый демонстрационный этап, только Python + Tkinter из стандартной поставки CPython для Windows. **Настоящий Codex, app-server, GitHub, модель, подписка и сеть здесь не используются.** Этот прототип не умеет автоматически возобновлять задачи после исчерпания лимита.

## Как запустить на Windows

1. Установите обычный Python 3.11+ с модулем Tkinter (на Windows он обычно входит в официальный установщик Python). Проверить: `python --version`, `python -m tkinter`.
2. Клонируйте этот репозиторий и откройте **обычный PowerShell** в его каталоге. Рабочие проекты и глобальные настройки Codex трогать не нужно.
3. Запустите:

   ```powershell
   python -m supervisor
   ```

4. Откроется отдельное окно **Codex Supervisor · прототип (демо)**.

Команда **не вызывает** `codex.exe`, не требует авторизации и не запускает дочерние процессы. Не нужен запуск от администратора, `pip install` или подключение к API.

## Что проверить вручную

- Выбрать «Демо-проект», отправить сообщение в несколько строк с **Ctrl+Enter** или кнопкой «Отправить». Ответ появится с пометкой «Фиктивный агент».
- Отправить сообщение и быстро нажать «Пауза»: ответ завершится, затем статус «Пауза». «Продолжить» откроет ввод.
- Отправить сообщение и нажать «Стоп»: запланированный mock-ответ **не должен** появиться; остановленную сессию нельзя заново запустить без «Новая сессия».
- Нажать «Завершить»: дальнейшая отправка в этой сессии заблокирована.
- Добавить новый демо-проект: переписки независимы. Создать новую сессию в том же проекте.
- Нажать «Лимит · демо»: будет только ручное ожидание; «Продолжить» вернёт в режим «Готов». **Таймеров, реального восстановления квот и автоматических модельных ходов нет**.
- Закрыть окно и открыть снова: выбранный проект, переписка и состояние остаются. При попытке открыть **второй экземпляр** с тем же каталогом данных он должен отказать.
- Для проверки аварийного восстановления можно начать mock-запрос и аварийно закрыть окно до ответа; после запуска незавершённый ход будет `Нужна проверка`, без автоматического повтора. Не требуется делать это на реальной сессии Codex.

## Где находятся данные

По умолчанию состояние сохраняется в:

- Windows: `%LOCALAPPDATA%\CodexSupervisor\state.json`.
- Linux/macOS (только для тестов, GUI официально рассчитан на Windows): `~/.local/share/CodexSupervisor/state.json`.

Для изолированного теста можно явно задать переменную окружения `CODEX_SUPERVISOR_HOME` на отдельную **пустую** папку. Запущенные экземпляры держат OS-level lock в `instance.lock`; файл не удаляется, kernel lock освобождается при закрытии. Состояние записывается во временный файл с fsync и атомарной заменой. Повреждённое JSON-состояние не перезаписывается и не удаляется автоматически.

**Важно:** история ваших введённых тестовых сообщений хранится на диске локально в открытом JSON, **без шифрования**. Для M1 не вводите секреты, реальные проекты и приватные клиентские данные. Список проектов — только названия: эта программа не открывает и не меняет реальные папки.

## Автоматические проверки (без GUI, модели и сети)

```powershell
python -m unittest discover -s tests -v
```

Проверяется изоляция проектов, неиспользование чужой сессии, отправка/пауза/стоп, отказ от дублирования, сохранение и перезапуск, обработка повреждённого состояния, второй экземпляр и атомарная запись.

## Ограничения текущей версии

- Диалог генерируется детерминированным Python mock. Подключение Codex app-server — **M2**, не M1.
- Нет аутентификации, загрузки существующих Codex threads, управления другим CLI, портов и внешнего сетевого трафика.
- Windows GUI необходимо подтвердить пользовательским запуском: успешные unit-тесты не доказывают правильную отрисовку Tkinter на чужом ПК.
- Пауза реализована **после текущего демонстрационного хода**, а Стоп отменяет выдачу ответа; у реальных инструментов Codex семантика отмены будет другой и потребует испытаний.
- По умолчанию не создаётся служба Windows, автозапуск или планировщик.
