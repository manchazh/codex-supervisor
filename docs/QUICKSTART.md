# Настройка ChatGPT + GitHub + Codex: старт для Windows

Это инструкция **для обычного рабочего процесса**. Само приложение Codex Supervisor ещё разрабатывается. Не нужно ждать его выпуска, чтобы использовать методику.

## Что понадобится

- Windows 10/11, установленный **Git**.
- Установленный **Codex CLI** и действующий доступ к нему. Используйте [официальную документацию Codex](https://developers.openai.com/codex/cli) для актуального способа установки и входа. Поддерживаемые варианты авторизации и модели могут меняться.
- Аккаунт GitHub, репозиторий для проекта и разрешение работать с ним.
- ChatGPT для постановки задач и независимого ревью. Подключение GitHub — **по желанию**: с ним проще читать Issues/PR и создавать их из чата, если доступные инструменты позволяют. Если интеграция недоступна, используйте веб-интерфейс GitHub.

Не устанавливайте случайные бинарники, не вставляйте токены в чат и не передавайте их агенту в коде.

## 1. Проверить инструменты

Откройте **PowerShell** обычным способом, без администратора. Отдельно проверьте:

```powershell
git --version
codex --version
codex --help
```

Если команда `codex` отсутствует — проверьте официальный установщик/документацию. Не копируйте чужую команду установки без проверки её происхождения. Перед обновлением сохраните активную работу и убедитесь в совместимости CLI.

## 2. Завести проект в GitHub

Создайте свой репозиторий — **публичный или приватный согласно содержимому**. Для коммерческой разработки обычно начинайте с приватного.

В PowerShell клонируйте **свой** репозиторий (замените пример):

```powershell
git clone https://github.com/OWNER/PROJECT.git
cd PROJECT
git status
```

Если доступ требует авторизации, используйте официальный Git Credential Manager или GitHub CLI. **Не кладите access token в URL клонирования, команды, `.env` или Issue.**

GitHub CLI (`gh`) удобен, но **не обязателен** для самого Codex. Создавать Issues и PR можно и через сайт.

## 3. Настроить правила проекта

Создайте в корне своего проекта `AGENTS.md`. В нём опишите:

- язык ответов и документации;
- какие файлы читать перед изменениями;
- как выбирать рабочие ветки;
- обязательные проверки;
- запреты: секреты, production, удаление, merge без разрешения.

Используйте [шаблон задач и пример правил](WORKFLOW.md) и [AGENTS.md этого репозитория](../AGENTS.md) как основу. **Не копируйте пути, зависимости или разрешения другого проекта без проверки.**

## 4. Работать в связке

**В ChatGPT:** опишите цель и попросите составить понятную GitHub Issue с критериями приёмки. Создайте её через доступную интеграцию GitHub либо через сайт. ChatGPT выступает постановщиком и ревьюером, но **не видит локальные изменения Codex автоматически**.

**В локальном Codex:** откройте проект из его каталога. Попросите прочитать `AGENTS.md` и выполнить **только Issue №N** в отдельной ветке, проверить код, подготовить PR и остановиться. В запросе можно дать URL задачи и необходимые ограничения.

**После PR:** попросите ChatGPT проверить фактический diff, а не только описание PR; сравните требования и тесты. Пользователь принимает изменения и отдельно разрешает merge.

## 5. Возобновление

Для официального механизма восстановления используйте `codex resume --help`, затем `codex resume` или конкретный ID, если он известен. **Не путайте** восстановление переписки с автоматическим продолжением незавершённой задачи: это разные функции. Убедитесь, что ветка и рабочая папка соответствуют сессии.

## 6. Разрешения и Windows sandbox

Проверяйте, какой режим доступа запущен в вашей версии (`codex --help`):

- `workspace-write`: ограниченная запись в текущую рабочую область; базовый безопасный выбор для проверки.
- `on-request`: отдельные действия могут потребовать разрешения пользователя.
- `danger-full-access`: существенно более широкий доступ, **не универсальное решение проблем с approvals**.

Встречаются сбои инициализации песочницы Windows, при которых даже чтение/проверки требуют запуска вне sandbox. **Сначала диагностируйте причину**, а не добавляйте разрешения на все PowerShell/Python/Git-команды и не отключайте защиту. Если агент предлагает «разрешить навсегда», оценивайте точный префикс и последствия.

Частый вопрос: «Почему ChatGPT проверил PR, а Codex всё равно попросил разрешение?» — потому что **проверка результата человеком и sandbox approval относятся к разным уровням безопасности**.

## 7. Чего не ждать от связки

- ChatGPT **не управляет** локальным Codex без специально настроенного транспорта/клиента.
- GitHub Issue **не выполняется автоматически** только потому, что она создана.
- Codex может ошибиться: тесты и ревью обязательны.
- В публичный репозиторий может попасть всё, что вы добавили в коммит, даже если позже удалили файл. Проверяйте `git diff` перед публикацией.
- Нельзя надёжно угадать время восстановления квоты из произвольной ошибки HTTP 429.
