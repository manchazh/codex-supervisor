# Безопасная проверка квот через локальный Codex app-server (разовый RPC)

Этап исследования Issue #12. **Не фоновый монитор, не автопродолжение, не рабочая интеграция**.

## Цель

Проверить, доступен ли **отдельному клиенту** метод `account/rateLimits/read` при подключении к уже работающему daemon Codex. Нужен обычный PowerShell и стандартный Python 3.11+.

Используем только документированные read-only вызовы app-server JSON-RPC:

1. `initialize` — представиться серверу.
2. `initialized` — закончить handshake.
3. `account/rateLimits/read` — один раз прочитать квоты.

**Ни одного** `thread/start`, `thread/resume`, `turn/start`, команд модели, approvals, действий Git или сервиса Windows. Дочерний `codex app-server proxy` получает stdio, возвращает результат и закрывается; сам daemon остаётся запущенным. Не открываем входящий порт.

## Предварительные условия

- `codex app-server daemon version` уже показывал **running**.
- Клиентская TUI успешно работает с `--remote unix://`.
- Перед реальным запуском прочитать код скрипта и получить разрешение владельца тестовой Windows-машины.

## Команда после согласования

Из корня **отдельно клонированной ветки `issue/12-readonly-quota-rpc`**:

```powershell
python -m quota_probe
```

По умолчанию таймаут 12 секунд. На экране только два окна: использованное/оставшееся %, длительность и reset (если сервер вернул данные), плюс нейтральные ошибки. Исходный JSON RPC **не выводится**, поскольку может содержать email, токены, account ID, идентификаторы или пути. Не пересылайте сырые журналы локального сервера.

Программа может выполнить **сетевое обращение сервера за текущими квотами**, но **не делает модельных запросов и не расходует модельные токены**. В случае ошибки не повторяйте бесконечно и не меняйте параметры безопасности.

Важно: даже успешно полученные `resetsAt` **не являются доказательством**, что Codex реально разрешит новый turn после сброса квоты. Из двух числовых окон нельзя достоверно получить `ordinaryUsageAllowed` без отдельного подтверждения схемы сервера. Фоновый монитор/восстановление разрабатываются отдельно.

## Автоматические тесты без Codex и сети

```powershell
python -m unittest discover -s tests -p "test_quota_probe.py" -v
```

Тестовый сервер — только отдельный фиктивный subprocess Python. CI на Windows и Linux проверяет handshakes, белый список методов, отсутствие приватных полей в выводе, обработки ошибок и некорректных данных.

## Ограничения и безопасность

- Не выполняет действий при исчерпании квоты; не обрабатывает приходящие запросы approvals и не связывается с конкретным рабочим thread.
- Не трогает файлы `~/.codex` или пользовательский `config.toml`; сам Codex-сервер может использовать собственный сетевой запрос или кеш для получения квот.
- Не меняет настройки Windows, ACL, Codex daemon, sandbox или состояния TUI.
- В случае таймаута завершает только **свой** дочерний `proxy`, не daemon.
- Если server сообщает не ту структуру, открытый JSON не показываем; нужен отдельный адаптер под версию CLI.
- В будущей версии интервалы запросов должны быть умеренными и учитывать уведомления `account/rateLimits/updated`, а не нагружать сервер постоянным опросом.
