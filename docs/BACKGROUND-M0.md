# Фоновый Codex Supervisor — M0 (PowerShell + обычный TUI)

**Дата:** октябрь 2026. **Состояние:** безопасная основа и offline-прототип. **НЕ умеет** подключаться к живому Codex, читать реальные лимиты или автоматически продолжать задачу.

## Утверждённая концепция

Запускается обычный Codex в PowerShell, а **Supervisor работает постоянно рядом** на протяжении управляемой сессии. Он отслеживает подтверждённые события сессии и квот, не вмешиваясь в каждую реплику. При исчерпании подписочной квоты он ждёт её **достоверного** восстановления и должен возобновить то же незавершённое поручение/точный thread без вручную введённого «продолжай».

Никаких отдельных дневных/ночных режимов и обязательного нового GUI. В штатной работе пользователь видит знакомый Codex. Статус Supervisor можно получать из обычного терминала. Закрытие ПК или переход в сон означает, что фоновое ожидание не исполняется; постоянный запуск вместе с Windows **не включается без согласия**.

## Как запустить M0 без риска

Нужен только Python 3.11+ из официальной установки. Из корня репозитория, **в обычном PowerShell и НЕ внутри работающей модели**:

```powershell
python -m background_supervisor doctor
```

Читает только `codex --version`, `codex --help`, `codex resume --help`, `codex app-server --help`. **Не запускает app-server, не соединяется с живыми сессиями и не отправляет сообщения модели.** `doctor` сообщает лишь, присутствуют ли флаги на этой машине. Это проверка синтаксиса, не совместимости рабочего канала.

Для демонстрации фонового цикла без сети/модели:

```powershell
python -m background_supervisor demo --ticks 8
```

Видно последовательность: «работает → подтверждённый mock-лимит → ждёт полный snapshot → защитная пауза → сервер разрешил → одна фиктивная готовность продолжить». **Вызов `turn/start` отсутствует.** Для бесконечной имитации ожидания с явной остановкой `Ctrl+C` задайте `--ticks 0`; это не настоящий монитор Codex, а постоянно работающий симулятор.

Проверки:

```powershell
python -m unittest discover -s tests -p "test_background_m0.py" -v
```

## Архитектурная развилка, ещё НЕ проверенная на Windows

```text
PowerShell (обычный Codex TUI, в будущем remote client)
                     |
              единый thread
                     |
        управляемый canonical app-server
                     |
       пассивный Supervisor (typed RPC)
                     |
      квота / состояние / пауза / продолжение
```

Нельзя безопасно «приставить» Supervisor к произвольному уже открытому Codex через клавиши, управление мышью или два независимых процесса `codex resume`. Предполагается отдельный **управляемый запуск** обычного TUI, при котором сервер является одним владельцем истории. Запуск второго независимого Codex в том же workspace запрещён до проверки конфликтов.

Существуют `--remote` и `app-server` в CLI и экспериментальные механизмы daemon; официальная документация предупреждает, что жизненный цикл app-server daemon может меняться. **Точно работающее сочетание transport/auth в Windows, TUI и observer ещё не доказано.** Не включать автоматически сетевой listener, открытый порт или глобальную службу.

Официальные ориентиры:
- https://github.com/openai/codex/blob/main/codex-rs/cli/src/main.rs
- https://github.com/openai/codex/blob/main/codex-rs/app-server-daemon/README.md
- https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/GetAccountRateLimitsResponse.json

## Требования к реальному наблюдателю

- **Источник истины:** структурированные события Codex и свежие серверные quota snapshots для того же аккаунта, модели/limit bucket и thread. В M0 события только симулируются.
- **Не расходовать модельные токены на опрос квоты.** Будущий запрос `account/rateLimits/read` сам по себе не является модельным turn; частота опроса, связь с backend и стоимость должны быть подтверждены на реальной версии.
- **Не принимать любой HTTP 429 за подписочный лимит**. При `willRetry=true` не создавать собственный повтор.
- **Проверка всех блокирующих окон:** после максимального `resetsAt` плюс защитная пауза, свежий `ordinaryUsageAllowed === true` и тот же account/limit.
- После неизвестного исхода последней команды/turn — остановка для человека, **без дубля Git/PR/модельного хода**. Завершённая задача никогда не возобновляется по таймеру.
- Пауза/Стоп пользователя сильнее таймера. Полные переписки, секреты, токены и личные пути не копировать в лог.
- Создание нового turn — в отдельном согласованном этапе; M0 выдаёт только **внутренний mock intent** и не умеет работать с реальной моделью.

## Следующие контрольные точки

1. Пользователь выполняет только `doctor` в обычном PowerShell и передаёт вывод. Диагностика не трогает активные сессии.
2. После оценки доступных возможностей подготовить конкретный план **тестового remote TUI без нового модельного сообщения** в отдельном тестовом проекте, без перенастройки daemon или sandbox.
3. Только после нового согласия — один реальный внешний модельный turn в изолированном проекте с проверкой совпадения thread/истории.
4. Проверить структурированное чтение квоты и серверный reset на реальном счёте, без искусственного исчерпания подписки, без попыток обхода и без таймеров наугад.
5. Затем подключить постоянно работающий Supervisor, который наблюдает и продолжает уже начатую работу. До проверки — **не заявлять готовность автопродолжения**.

## Существующий GUI и Windows sandbox

Tkinter MVP в незалитом PR #9 — запасной вариант. Не требуется для M0. На некоторых Windows-сборках Codex ошибку создания sandbox вызывает общий runtime `node_repl.exe`; это дефект окружения, а не повод отключить изоляцию. Ни одна команда этого этапа не завершает чужие процессы, не меняет ACL и не запускает установку.

## Неочевидное

`doctor` может сообщить `supports_remote_tui=True`, но реальная совместимость транспорта и отображения **всё равно неизвестна**. `demo` может дойти до `READY`, но это **не разрешение делать модельный ход**: токены не расходуются и с настоящим Codex ничего не происходит.
