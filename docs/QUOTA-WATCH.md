# Непрерывный фоновый наблюдатель лимитов Codex — M1

**Статус:** наблюдает за реальными лимитами; **автопродолжение реального Codex пока НЕ реализовано**. Никакого нового GUI: обычный Codex TUI остаётся открытым в своём PowerShell, а наблюдатель работает в соседнем.

## Что уже доказано

На Windows пользователя с Codex CLI / управляемым app-server v0.162.1 отдельный `python -m quota_probe` успешно прочитал 5-часовое и недельное окна через `codex app-server proxy` с WebSocket. Эта проверка не посылала модельные ходы. Новый watcher использует тот же однократный метод чтения, повторяемый с бережным интервалом. Показатель «осталось 99%» не является основанием для самостоятельного отправления следующего модельного turn.

## Запуск

Из отдельной клонированной тестовой ветки `issue/14-quota-watch`:

```powershell
python -m quota_probe.watch_cli
```

Оставьте второе окно PowerShell открытым. По умолчанию каждые **300 секунд (5 минут)** программа запускает **свой собственный** `codex app-server proxy`, выполняет только `initialize`, `initialized` и один `account/rateLimits/read`, и закрывает proxy, **не останавливая** основной app-server daemon и Codex TUI. В этой версии мы намеренно выбрали изолированные короткие соединения вместо экспериментального долговременного subscriber; это менее эффективно, но проще для безопасной диагностики. Постоянное соединение + уведомления `account/rateLimits/updated` — следующий этап после реального подтверждения поведения на текущем сервере.

Для приёмочного наблюдения с минимальным разрешённым интервалом (1 минута):

```powershell
python -m quota_probe.watch_cli --interval 60
```

Диапазон 60–3600 секунд, изменить через параметр. Программа печатает только первый снимок или изменения числовых полей; между ними бездействует. При ошибках делает паузу 60, 120, 240, 480 и максимум 900 секунд. Никакого busy loop.

**Остановка:** в окне наблюдателя `Ctrl+C`; Codex daemon и все существующие Codex-сеансы остаются запущенными. Монитор работает только пока его процесс и ПК работают; Windows Service, автозагрузка и работа после выключения **не реализованы**.

## Безопасность

- Ни `turn/start`, ни `thread/resume`, ни изменений в Git, sandbox, ACL, `~/.codex`, daemon/settings.json.
- Второй watcher в том же каталоге получает ошибку эксклюзивной OS-блокировки.
- Локальный файл **только с числовыми метаданными** хранится в `%LOCALAPPDATA%\CodexSupervisor\quota\last-seen.json`. Нет email, accountId, UUID, содержимого переписки и токенов. Состояние сохраняется атомарно; повреждённое не стирается.
- Файл блокировки `watch.lock` остаётся после закрытия, но системная блокировка снимается автоматически.
- Не вводите пароли и секреты в тестовый PowerShell. Ответ RPC целиком не печатается.
- Достижение `resetsAt` выводит лишь информационное сообщение: **это НЕ доказательство фактической доступности нового хода**, даже если процент изменился. Любое автоматическое продолжение требует отдельного подтверждения серверного статуса и безопасного состояния конкретной задачи.

## Ограничения

Монитор пока сравнивает **два окна квот только по значениям**, не отслеживает `usageLimitExceeded` от конкретной сессии, `ordinaryUsageAllowed`, пользовательский pause/stop или готовность и завершённость задания. Он **НИКОГДА не отправляет модельный ход**. Проценты могут меняться вследствие работы иных Codex клиентов. Фоновое наблюдение не гарантирует точный момент восстановления: задержка до выбранного интервала опроса.

## Offline tests без Codex / токенов

```powershell
python -m unittest discover -s tests -p "test_quota*.py" -v
```

Тестируется WebSocket RPC через фальшивый subprocess, парсинг двух окон, перезапуск, OS lock, таймауты/backoff, отсутствие лишних записей, повреждённый JSON и невозможность принять reset как команду отправки модели.
